# 专利云 · 案件全生命周期管理

所内自研的专利案件管理平台。当前里程碑：**官文与期限**（官文驱动八态流转 + 双起算/三口径期限引擎 + 月周日历 + 双口径完成度），前序里程碑：整体骨架、案件作战台、委托与客户。

## 一键启动

```bash
docker compose up -d --build
```

打开 **http://localhost:8103** 即是真实在办业务（首次启动自动灌入演示数据）。

| 服务 | 端口 | 说明 |
|---|---|---|
| frontend (Nginx) | **8103** | 静态资源 + `/api` 反代到 backend:7103 |
| backend (Express) | **7103** | REST API |
| mysql | 3316 → 3306 | 调试用暴露，生产可删 |
| redis | 6383 → 6379 | 调试用暴露，生产可删 |

## 业务规则

### 委托链路（建档 → 签约 → 受理派案）
1. 管理员「客户建档」→ 2. 签订委托合同（客户状态→已签约）→ 3. 案件登记受理通知书并指派代理人（申请→受理）。
状态机统一拦截非法操作并说明原因：未签约受理 → `409 该客户尚未签署委托合同`；未派代理人 → `409 NO_AGENT`；**非法跃迁**（如实审→受理）→ `409 ILLEGAL_ROLLBACK`；跳步 → `ILLEGAL_TRANSITION` 并提示当前可登记的下一步；越权角色 → `403`。正常流程一律通过登记官文推进，`/transition` 仅作异常状态更正入口。

### 官文与期限（本里程碑）

**官文驱动八态状态机。** 案件在 `申请 / 受理 / 初审 / 实审 / 授权 / 驳回 / 复审 / 无效` 八态间流转，唯一事实入口是「登记官文」：受理通知书、初审合格（公布）、进入实审、实审意见、授权办登、驳回决定、复审受理/复审意见/复审三决定、无效受理/无效两决定等。每条状态边显式白名单到**具体官文类型**——状态允许来回（驳回→复审、复审→实审/授权/驳回、授权→无效→授权/驳回），但禁止跳步、禁止非法跃迁，也禁止用「复审改判授权」在实审阶段直接授权这类**跨程序混用**（返回 `409 ILLEGAL_OA`）。

- **官文可撤回**：撤回必填原因并留痕；派生的未完成期限随官文作废（已完成的保留留痕）；案件状态按「撤回后仍有效的状态类官文链」重放恢复，全部撤回则回到「申请」。
- **过程性官文**（实审意见、复审意见、其他）不改变状态，但只允许在其所属程序阶段登记，并自动派生答复期限。

**期限两条口径是雷区，界面一律明示，不让代理人猜。**

- **起算口径** `base_type`：`receive` 自收到日起算（未登记实际签收日时，推定收到日 = 发文日 + 推定送达天数，默认 15 日，界面标注「推定收到」）；`dispatch` 自发文日起算；`manual` 直接指定到期日。发文日与收到日相差数天，期限卡同时展示起算口径与起算日。
- **天数口径** `day_basis`：`natural` 自然日 / `workday` 工作日（剔周末）/ `legal` 法定节假日口径（剔周末与法定休假日、计入调休上班日）。内置 2025–2027 国务院放假安排（春节、清明、五一、端午、中秋、国庆及调休），可用库表 `holidays(kind=holiday/workday)` 覆盖。到期日落法定休假日依法顺延到假后第一个工作日（春节、国庆场景均有单测）。
- **UTC 存储、按代理所时区显示**：期限/时刻全部 UTC 入库，所级设置 `firm.timezone`（默认 `Asia/Shanghai`，管理员可改）决定「当地今天」与时刻展示；倒计时以服务端给出的所内今日计算，跨时区不会多一天/少一天。

**月/周两视图，三断点各出一版。** 顶部导航「官文与期限」进入日历：桌面为全宽月历/周历网格 + 当日事项；平板（≤1024px）为左迷你日历 + 右事项双栏；手机（≤640px）为按天的竖向卡片流。落点超期办结触发**二次确认 + 必填逾期原因**，写入 `deadlines.overdue_reason`（办理人/时间/原因）永久留痕。三种空态/错误态分开写：**加载失败**（含离线无缓存）、**该案无官文**、**官文全部撤回**（列撤回原因与状态恢复结果），绝不统一成「暂无数据」。

**完成度双口径，作战台/详情/导出三处一致。** 同一纯函数 `lib/completion.js` 输出：

- **已归档官文数口径** = 有效（未撤回）官文数 ÷ 4 份必经主线官文（受理/初审公布/进入实审/审查结论），多通意见会计入分子并可封顶 100%；
- **关键阶段数口径** = 已完成关键阶段 ÷ 5（受理→初审→实审→审查结论→程序终结），半截官文不会抬高它。

半截官文的案子两口径相反（意见发了好几通但还卡在实审：官文口径 100%、阶段口径 60%），界面在每处都标明口径并给出分歧提示；CSV 导出（`/api/export/cases.csv`）两口径各自成列，数字与接口严格同源。

### 脱敏与留痕
- 案件立项后，所内人员看到的客户名一律为 **缩写·编号**（如 `HX·KH-0001`）；委托中的案件不脱敏；客户管理员看本客户始终明文。
- 查看全称必须二次确认 + 填写理由 → 每次查看写入 `unmask_logs`（查看人/理由/IP/时间），管理员与审核员在「留痕」页可审计。

### 客户隔离
`client_admin` 绑定 `client_id`，所有查询按租户过滤；直接访问他人客户/案件返回 `403 FORBIDDEN`，前端渲染带说明的错误页（非空白页）。

### 离线（代理人出差场景）
- **不拿旧状态糊弄**：断网时顶部横幅明示「离线模式」，所有缓存数据带「更新于 HH:mm，可能已过期」标记；无缓存则明确报错而非空白。
- 变更进入 IndexedDB 待同步队列（页面可见「待同步」条目），恢复网络后自动提交 `/api/sync/batch` 合并。
- **幂等不产生重复案件**：案件创建携带客户端 `client_uuid`（数据库唯一约束兜底）+ 每次变更带 `Idempotency-Key`（Redis + MySQL 双存储，重放返回首次结果）；状态流转按服务器当前状态重新校验——仍合法则合并执行，目标已达成视为重复，非法则标记 `conflict` 并保留服务器状态。

## API 概览

```
POST /api/auth/login|logout        GET /api/auth/me
GET  /api/dashboard                作战台聚合（八态漏斗/双口径完成度/期限，Redis 缓存 20s，写即失效）
GET|PUT /api/settings              所级设置（firm.timezone 代理所时区，仅管理员可改）
GET  /api/calendar?from&to&case_id 月/周日历数据（期限落点 + 官文发文落点）
GET  /api/export/cases.csv         完成度导出（两口径各自成列）
GET|POST /api/clients              GET /api/clients/:id
POST /api/clients/:id/contracts    签约（重复签约 409）
POST /api/clients/:id/reveal       查看全称（理由必填，留痕）
GET|POST /api/cases                GET /api/cases/:id（详情含官文链/期限口径快照/双口径完成度）
POST /api/cases/:id/office-actions       登记官文（驱动状态 + 派生期限）
GET  /api/cases/:id/office-actions       官文与期限列表
POST /api/cases/:id/office-actions/:oaId/withdraw   撤回官文（原因必填，状态恢复/期限作废）
POST /api/cases/:id/transition     异常状态更正（状态机校验；正常流程走官文）
POST /api/cases/:id/deadlines|fees 手工期限（支持双起算×三口径推算或指定到期日）/ 费用
POST /api/ops/deadlines/:id/complete   办结（逾期需 confirmed + reason，409 NEED_OVERDUE_REASON 二次确认）
POST /api/ops/fees/:id/pay         缴费（幂等）
GET  /api/ops/agents               GET /api/logs/unmask|events
POST /api/sync/batch               离线变更批量合并（case.create / case.transition / oa.register / oa.withdraw / deadline.create|complete / fee.pay）
GET  /api/health
```

所有变更类 `POST` 支持 `Idempotency-Key` 请求头：相同 key 重放返回首次响应（`X-Idempotent-Replay: true`）。

## 目录结构

```
├── docker-compose.yml        # mysql / redis / backend:7103 / frontend:8103
├── mysql/init.sql            # 建库建表（种子数据由后端首启写入）
├── backend/
│   ├── src/lib/              # 状态机、期限引擎(deadlines)、节假日(holidays)、官文目录、完成度、脱敏（纯函数，可单测）
│   ├── src/middleware/       # JWT 鉴权、租户隔离、幂等
│   ├── src/services/         # 业务核心：官文、日历、作战台、导出、所级设置（路由与离线合并共用）
│   ├── src/routes/           # REST 路由
│   ├── src/drivers/          # mysql（生产）/ sqlite（开发测试）
│   └── test/                 # node:test 单元 + 集成
└── frontend/
    ├── src/views/            # 作战台 / 官文与期限日历 / 委托与客户 / 案件 / 留痕
    ├── src/components/       # 日历事项、官文登记、逾期确认、完成度仪表等
    ├── src/offline.js        # IndexedDB 缓存 + 待同步队列
    └── public/sw.js          # 应用外壳离线缓存
```
